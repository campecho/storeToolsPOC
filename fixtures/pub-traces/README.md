# Golden `pub2raw` traces

Checked-in callback traces for the `.pub` import pipeline (plan §10.2). They are
the unit-test goldens for the trace parser + mapper **and** the fixture-mode
payload the import route serves when the `pub2raw` binary is absent
(plan §10.1 — dev/CI/demo run with no native dependency).

## Provenance

`demo-flyer.trace` is **synthetic**: generated by `trace-emitter.cpp`, which
drives librevenge 0.0.5's `RVNGRawDrawingGenerator` — the exact generator
`pub2raw` wraps around libmspub — with a demo-flyer callback sequence. The
property vocabulary (`svg:x`, `draw:fill`, `librevenge:rotate`,
`fo:padding-*`, …) was extracted from `libmspub-0.1.so.1` itself, so names
match what real conversions emit. The **format** is therefore byte-exact;
the **callback sequence** is authored, not parsed from a real publication.

Format quirks this ground truth pinned down (encoded in `trace-parser.ts`):

- some callbacks print a space before `(` (`drawRectangle (…)`), others
  don't (`setStyle(…)`);
- `librevenge:rotate` prints degrees with a bogus `in` unit suffix;
- vector properties nest parenthesized property lists;
- `office:binary-data` prints as base64;
- `insertText (…)` payload is raw text, not a property list.

Regenerate (needs `g++ librevenge-dev pkg-config`):

```bash
g++ -o trace-emitter trace-emitter.cpp \
  $(pkg-config --cflags --libs librevenge-0.0 librevenge-generators-0.0 librevenge-stream-0.0)
./trace-emitter > demo-flyer.trace
```

## Real-corpus traces

Traces from **real store `.pub` files** (plan §10.6's corpus) belong here as
they're gathered: `pub2raw file.pub > name.trace` inside the Docker image (or
any machine with `libmspub-tools`). Real traces supersede the synthetic one as
goldens; keep `demo-flyer.trace` as the fixture-mode demo payload.
